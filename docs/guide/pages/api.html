Cette référence s’adresse aux personnes qui souhaitent automatiser une publication. Le parcours normal ne demande pas de code : utilisez le Designer.

L’API de développement peut encore évoluer. Les accès sont authentifiés. Ne placez pas de clé dans une URL ni dans un dépôt public.

Lire les compositions

GET /designer/api/state renvoie la composition courante, sa révision, les modèles et les états des écrans. Utilisez l’en-tête Authorization: Bearer <clé du Companion>. Les sessions ouvertes par le Companion peuvent aussi utiliser leur cookie.

Publier avec protection contre les conflits

POST /designer/api/publish reçoit un objet JSON contenant config, targets et base_revision. Partez d’une configuration lue dans l’état ou d’un modèle renvoyé par l’API.

{
  "config": "Remplacer par l’objet de composition",
  "targets": ["000000000001"],
  "base_revision": 0
}

Cet exemple illustre l’enveloppe, pas une requête valide complète. Remplacez l’identifiant fictif par celui d’un écran enregistré. Une révision de départ différente de la révision actuelle est refusée pour éviter d’écraser une publication concurrente.

La requête doit utiliser Content-Type: application/json. Les modifications depuis une session web demandent également le jeton CSRF de cette session. La taille maximale du corps est de 32 768 octets.

Retour à la version précédente

POST /designer/api/rollback reçoit {"base_revision": 1}, avec la révision courante. Le retour produit une nouvelle révision et attend, lui aussi, la confirmation des écrans.

Échanges du firmware

GET /v1/designer/frame?device=…&applied=…&sleeping=… enregistre la présence et la dernière version appliquée. Il fournit uniquement la composition assignée à cet écran, ses valeurs et les vols admissibles.

POST /v1/designer/action reçoit device, page et action. Une action doit appartenir à la page publiée pour cet écran. Les commandes Home Assistant acceptées sont limitées aux commandes prévues par le modèle.

Ces routes firmware exigent la clé Bearer; une session web seule ne suffit pas. Le nouveau moteur confirme l’affichage d’une composition, sans confondre réception et application.
